# 5. Риски и ограничения

## 5.1. Данные

| Ограничение | Влияние | Что сделано / что можно сделать |
|---|---|---|
| API не отдаёт часть заменённых версий пунктов плана, на которые ссылаются договоры (в основном 2026 год) | У позиций нет единицы измерения | Единица выводится по плану заказчика и типичной единице кода (99% верно на проверке); 7 682 позиции без единицы исключены из сравнения цен |
| У рыночных договоров нет лотов и объявлений в базе, у части нет `trdBuyId` | Нет места поставки (15% позиций) и ссылки на объявление | Аналоги без ссылки идут в Top-K последними, ответ это поясняет; в `market.py` поля добавлены — при перевыгрузке рынка ссылки появятся |
| Договоры без конкурса имеют `trdBuyId = 0` | Нет ссылки на объявление | Ответ поясняет; идентификатор — ID договора |
| Рыночная выборка — 100 кодов с наибольшей суммой (97% суммы 27 организаций), до 1 000 договоров на код и год | Fair Price есть у 48,6% позиций (79,7% суммы) | Остальное — ограничение «недостаточно аналогов», а не выдуманная цена |
| 2026 год — по дату загрузки | Год неполный | Объёмы считаются по плану (годовому); в ответах есть пометка |
| Классификатор не различает марки (АИ-92 / АИ-95) и комплектации | Под одним кодом — разные товары | Ограничение указано в ответах; большой разброс снижает уверенность |
| Названий КАТО нет в выгрузке; город распознаётся только для Астаны, Алматы, Шымкента | Вопросы про другие города не фильтруются по городу | Догрузить справочник КАТО и названия областных центров |
| Сравнение «Одна услуга» / «Работа» между договорами условно | Объём услуги в каждом договоре свой | Уверенность по таким позициям всегда низкая |

## 5.2. Методы

| Ограничение | Влияние |
|---|---|
| История — 2024–2026 годы | Для 2025 года база сравнения объёмов — один год |
| Пороги (30%, ×10, z ≥ 3,5, ≥ 5 сделок от ≥ 3 заказчиков, сезонность 5–30%) — экспертные | Влияют на число найденных аномалий; вынесены в SQL и легко меняются |
| Isolation Forest без разметки | Нельзя посчитать точность ML; ML — один из трёх сигналов, итог «высокий риск» требует совпадения с правилами или статистикой |
| Результат анализа — **сигнал для проверки**, а не доказательство нарушения | Решение о нарушении — за экспертом; каждый вывод снабжён ID закупок и методом |

## 5.3. AI-агент

| Ограничение | Влияние | Что можно сделать |
|---|---|---|
| Разбор вопроса — правила + словарь синонимов | Обобщение на новые формулировки ограничено: на отложенной выборке до доработки — 25,7% фактов | Новые независимые наборы вопросов; LLM для извлечения параметров в JSON |
| Казахский язык у Qwen3-4B слабее русского | Отдельные казахские формулировки товаров распознаются неверно | Модель крупнее (8B+ при наличии GPU); fine-tuning на парах «фраза → код ЕНС ТРУ» |
| В казахских ответах переведены вывод, заголовки, вердикты и подписи; описание методики и часть ограничений — на русском | Ответ на казахском частично двуязычный | Перевести оставшиеся шаблоны в `agent/i18n.py` |
| Точность RAG — F1 0,62 / 0,82 (dev / test) на 38 фразах | Возможны лишние коды в выборке; агент показывает, какие коды подобраны и с какой близостью | Набор для настройки побольше (100+ фраз), cross-encoder для переранжирования |
| Наборы оценки небольшие (30 + 15 вопросов, 38 фраз) | Разброс цифр ±5 п.п. на одну фразу | Расширять наборы |
| Задержка с LLM — 2–7 с, первый запрос после простоя — до 50 с (загрузка модели) | Для вопросов без поиска товара — меньше 0,5 с | Держать модель загруженной (`OLLAMA_KEEP_ALIVE`) |

## 5.4. Инфраструктура и безопасность

| Риск | Мера |
|---|---|
| Утечка токена OWS / паролей | Только переменные окружения и Kubernetes Secret; `*.env` в `.gitignore`; агент не получает ни токена, ни пароля `etl` |
| Агент может изменить данные | Роль `agent_ro`: только чтение, режим read-only на уровне соединения, тайм-аут 60 с; запросы параметризованы, SQL «на лету» не генерируется |
| Изменение схемы API OWS v3 | Сырые ответы хранятся целиком (`jsonb`), разбор — в одном файле `db/transform.sql` |
| Размер образа — 3,6 ГБ (torch и модель) | Можно разделить на образы агента и ETL |
| Манифесты Kubernetes проверены на синтаксис, но не на кластере | Перед промышленным запуском — прогон в тестовом кластере |
| LLM требует GPU для приемлемой скорости | Без LLM агент полностью работоспособен (правила + RAG) |
